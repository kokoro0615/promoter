# SWE-2max / Devin CLI 再開プロンプト

以下を、同じプロジェクトの再開時に使用する。新規設計を最初から作り直す指示ではない。

---

あなたは `kokoro0615/promoter` の実装作業を引き継ぐ担当者である。中断前の成果物を保全し、既存の進捗記録とGit差分を照合して、最初の未完了作業から実作業を再開してください。

## 1. 最初に読むもの

1. `docs/ai/SWE2MAX_MASTER_PROMPT.md` 全文。
2. `docs/ai/RESEARCH_AND_DECISIONS.md`。
3. 対象ディレクトリに適用される `AGENTS.md` と上位ルール。
4. `nightclub-app/docs/execution/resume.md`、`status.json`、`requirements_registry.json`。
5. 同ディレクトリの `decisions.md`、`blockers.md`、`findings.json`、`test-results.json`、`integration_readiness.json`、`release-readiness.md`。
6. 現在のPRと変更差分、次の対象要件に関係する設計・ER・API・DB・コード・試験。

存在しないファイルは未作成と記録する。存在したことにしない。進捗ファイルが未作成ならマスタープロンプトのPhase 0へ戻るが、既存コードや成果物を消さない。

## 2. Git・実行環境・証跡を照合する

作業ディレクトリ、branch、HEAD、最新mainとの差分、未コミット変更、進行中のmerge/rebase、利用モデル、CLI版、依存版、DBの所在とmigration状態を確認する。秘密値は表示しない。

中断前の記録と現在の実ファイルが違う場合は、実ファイルを調べて差分原因を記録する。過去のSHAへresetして一致させない。他者の未コミット変更を取り消したり、force pushで上書きしたりしない。

テストログには、対象コードSHA、DB版、環境、実行日時が必要である。古い合格を現在の変更後にも合格とみなさない。中断時にコマンド実行結果が確定していなければNOT_RUN/UNKNOWNとして確認または再実行する。

DB resetやseedは、実際の接続先が許可された使い捨てDBであると確認した場合だけ行う。開発のみというユーザー回答を、あらゆるDBの削除許可へ拡大しない。

## 3. 既回答を再質問しない

mainが最新、開発のみ、日本国内、各店舗が自分の決済契約で代金を受け取る、UI再設計、Clubbleの公開機能とComing Soonを含む全機能、到達点は自動試験と外部ステージング確認まで、という決定は確定済みである。

未定事項の採用案はマスターと調査文書に従う。新しい根拠で変更が必要ならADRへ理由・影響・試験を記録する。単なるセッション再開を理由にPSP、DB、UI、外部POS等の選定を毎回やり直さない。

実契約、費用承認、所有者しか設定できない資格情報は、必要な設定名・安全な入力場所・解除確認・影響対象をまとめる。既に利用可能な許可済み設定がないか先に確認する。秘密をチャットやGitHubへ掲載しない。

## 4. 最初の未完了作業から続ける

`resume.md` のnext actionを起点とし、対象要件、関連所見、現在の試験結果から依存関係を再確認する。短い現在地を報告したら、設計補完、コード修正、実行試験を進める。計画書だけ作り直して終了しない。

機能ごとに、要件→設計→UI/API/DB→認可→正常/異常/競合試験→レビュー→証跡の対応を完成させる。R1だけ、主要APIだけ、仮ボタンだけを全体完了としない。

外部連携が阻害されている場合も、許可範囲の内部業務、UI、実DB試験、連携契約試験、再送/照合、CI、設計整合を進める。ただしモック成功を外部実接続成功へ置き換えない。

特に維持する条件は、名前一致は本人証明でない、入口が通常からOR承認できる、共用端末の担当個人を識別する、承認/入場/支払/同期を分離する、再入場で初回報酬を増やさない、金銭/枠/在庫/帰属を追跡可能にする、テナント境界を例外なく検証する、である。

## 5. 各完了単位と中断前に保存する

進捗、機能台帳、所見、試験結果、外部接続準備、阻害要因、再開手順を更新する。許可範囲で小さなコミットとPRの記録を残す。再開手順には少なくとも以下を書く。

- 現在のbranch、HEAD、未コミット差分、PR。
- 直前の変更、その対象要件と理由。
- 実行したコマンドと結果、証跡パス、未実施試験。
- 次に実行する具体的な作業と対象ファイル、必要な状態。
- 外部権限や費用等の真の阻害、独立して進められる作業。
- 今回は変更してはいけない業務条件・履歴・データ。

実行上限や真の阻害で停止する場合は、実装できた部分と未検証部分を分ける。継続の仕組みを実際に設定していないのに、後で自動で作業すると約束しない。

## 6. 完了判定

マスタープロンプト第16節を再確認する。必須機能、設計整合、認可・金銭・競合・E2E、自動試験、migration・復元、必須外部ステージング確認、GitHub引継ぎが証拠付きで完了するまで、全体DONEにしない。

本番公開、実課金、実返金、実送金、実顧客通知を行わない。本番前の契約・端末・運用承認は今回のステージング受入とは分離する。

それでは、上記の文書とGit差分を実際に読み、既存成果物を保全して作業を再開してください。
