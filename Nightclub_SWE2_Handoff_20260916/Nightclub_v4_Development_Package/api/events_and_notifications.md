# 更新イベントと通知

`sync-event.schema.json`は最小無効化イベントの厳格な型。完全なUPSERT DTOを流す場合はOpenAPIのChangeEventと対象リソースの応答型を検証する。raw DB行、PIN、顧客連絡先、他紹介者の実績を配信しない。

|更新|画面反映|補助通知|受領の意味|
|---|---|---|---|
|登録・条件確定|入口当日一覧、自分のゲスト|通常は静かなバッジ|画面データ適用。既読ではない|
|承認待ち|入口と指定者の共通キュー|到着済みなど重要時に通知|通常承認は通知の成功に依存しない|
|承認/却下/差戻し|対象来店と申請版|申請者へ結果|最初の決定のみ。旧通知で再判断不可|
|入場・退場|入口/紹介者の実績|VIP来店など必要時のみ|売上全体が確定した意味ではない|
|取消・料金変更|対象の最新条件|重要変更の対象者|古い条件での入場を拒否|
|担当交代・権限失効|ロック/データ再取得|管理者へ必要時|古い購読とsnapshotの利用を停止|
|決済・予約例外|担当者の例外キュー|経理/予約担当|外部取引照合を優先|

内部Outboxは同一取引で保存、送信は少なくとも1回を前提とし、受信側が重複排除する。通知再送と業務コマンド再送を混同しない。Push・LINE・SMSは接続先/同意/費用の設定が整ったチャネルのみ有効化。チャネル選定未済を通知成功と見なさない。
