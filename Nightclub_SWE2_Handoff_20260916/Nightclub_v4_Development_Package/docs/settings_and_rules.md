# 可変設定・名前検索・判定ルール v4

**採用方針：FACT／High。以下の詳細：設計案／Medium。**

## 1. 可変値と開発範囲

対象者、金額、人数、期間は管理画面で変えられる。現在の金額を回答しないことは、仕様が何も決められないことを意味しない。開発は設定項目、型、公開フロー、優先順位、適用範囲、エラーを先に実装する。店舗は実営業公開前に値を入力する。

店舗テンプレート→営業の下書きpolicy_version→price_rules→個別permitsという境界。テンプレートの後日変更だけで既に公開した営業設定を無通知に変更しない。permitsは顧客本人か実登録者の一方を対象とし、同じ行に両方を曖昧に持たせない。

## 2. 優先順位

|順|確認|結果|
|---|---|---|
|1|所属・店舗・営業・対象・時刻・入力の有効性|不一致は拒否。省略判定へ行かない|
|2|入場停止・ハード上限・禁止条件|保留／不可。入口通常承認で上書きしない|
|3|一般に許可された通常／割引条件|STANDARDで確定|
|4|実登録者に有効な省略許可、代理対象・枠が一致|TRUSTED_ACTORで確定|
|5|来店の顧客IDに本人許可、期間・範囲が一致|CUSTOMER_PERMITで条件確定。ただし入場時の本人照合は残る|
|6|それ以外の申請可能条件|MANUAL申請。指定者と入口が通常判断|

複数許可を重ね掛けしない。申請した料金を根拠なく最安へ変えない。actorの省略枠を使うか顧客枠を使うかは順序とgrant IDで固定し、画面に根拠を示す。枠超過時に別人の許可へ無断で振り替えない。

## 3. 上限と同行者

UNSETは設定不足、LIMITED 0は許可数ゼロ、UNLIMITEDは管理者の明示許可。nullを無制限として扱わない。店全体のフリー上限と紹介者の省略上限は別bucket。紹介者の省略枠超過を通常承認した場合は、店の手動承認可能枠を使い、省略枠を負数へしない。

消費量＝初回入場消費＋未入場の確定引当。PENDINGでは引当しない。取消は未入場の引当だけを1回戻す。No-showの期限確定でも未入場引当を解放するが、当日の実入場消費は戻さない。再入場で新たな集客枠を消費しない。

顧客本人の許可は原則本人のみ。同行者に許可を広げるなら人数を明示。本人同伴必須か、同行者のみ先着可能かも管理設定する。本人必須の場合、本人未到着なら同行者の特典入場を確定しない。通常料金の別内訳は本人の了承を得て選択し、元申請の履歴を消さない。

## 4. 名前検索は本人証明ではない

原文display_nameとname_keyを分ける。検索キーはNFKC、空白整形、ASCII英字の小文字化、かなの補助キーを使う。漢字から読みを自動決定しない。異体字や同姓同名を同じcustomer_idに統合しない。[T15]

当日リストを最優先し、名前・読み・紹介者・予約の文脈で候補を絞る。「田中」2名なら2行を維持し、連絡先全桁ではなく必要なヒントと確認者の判断を使う。入力1文字の候補件数は上限とページングを設ける。原文に絵文字等があっても任意削除で同一人物と決めない。

紹介者が顧客を選んだ時点は候補紐付け。入口がKNOWN_BY_STAFF等の方法で本人照合した記録とは別。顧客許可を消費する入場は、その来店・顧客に有効なcustomer_checkが必要。電話番号・誕生日・QR・身分証画像を一律必須にしない。

## 5. 管理設定の公開

プレビューで設定不足、重複rule_key、時刻逆転、別店舗ID、無制限権限、同行者矛盾、現在使用量を下回る上限を検証。公開APIはexpected_versionとpreview_tokenを要求する。影響対象の変更があったら再プレビュー。NEW_ONLYは既存確定内訳を維持。REASSESS_UNENTEREDは対象を明示し、現在の営業の書込と直列化して適用する。

原子処理できる対象件数を超える場合はバックグラウンドで半端に条件を混ぜない。R1は操作を拒否して対象分割・営業時間外の管理作業へ案内する初期案。大量再審査を行う拡張はジョブID・ゲート・復旧の追加設計が必要。

## 6. Schemaで保証しないもの

JSON Schemaは形と型・必須・enumを検査する。[T20] 外部IDの存在と店舗所属、日時の前後、rule_keyの重複、入場時間が営業内か、金銭のcurrency一致、枠残数、本人同伴の成立はサーバーの業務検証。例ファイルはEXAMPLE_ONLYであり本番の運用値ではない。

## 7. 常連指定解除と事前許可の解除

常連区分と特典許可は別データだが、管理者の「常連指定を解除する」画面では有効な顧客許可を必ず同時に表示し、新規停止・未入場再審査の対象を確認する。初期設計案は区分だけを外して特典が無自覚に残る操作を不可にする。保存済みの入場履歴は変更しない。許可を残す特殊用途は別の管理操作・理由を必要とし、公開前の業務レビューで合意する。
