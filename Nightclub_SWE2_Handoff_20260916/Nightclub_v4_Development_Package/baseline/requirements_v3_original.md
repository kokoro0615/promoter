## Summary｜採用内容と本書の使い方

*FACT（ユーザー採用・v2継承） / Confidence：High*

対象は「プロモーター管理」だけでなく、プロモーター・DJ・スタッフ、店舗が招待した信頼済み紹介者を含む。紹介者と実際の登録者を分け、来店ごとに実績を記録する。[U1][U2]

### 業務の標準経路

> お客様から連絡 → 紹介者が登録 → 事前許可／権限で確定、または必要な承認 → 入口一覧へ自動反映 → 来店照合・支払確認・実入場 → 紹介者実績 → 営業締め・報酬

| 確定事項 | 解釈・実装上の境界 |
| --- | --- |
| 全員のWeb／PWA利用 | 店舗共通アカウントは使わない。約10名それぞれに個人ログインと必要な権限を付与する。 |
| 承認省略を採用 | 登録者の許可または顧客の事前許可をサーバーが判定する。「常連」と入力するだけでは承認を省略しない。 |
| 承認必要時はOR承認 | 指定承認者3名のうち最初の有効な確定操作を採用する。全員承認・2段階承認は要求しない。 |
| 受付一覧へ自動反映 | 通知の既読や入口の受領ボタンを、通常の受付成立条件にしない。 |
| 初期商用品質 | VIP予約・事前決済、テナント分離、バックアップ・復元試験、監査をR1から含める。 |

### 前提と影響

初期検証は1店舗・内部利用者約10名を想定。お客様のアプリ導入は不要。「常連」は第1章で紹介者と顧客に区別し、初期有効化対象をD-01で決定する。端末台数、POS、金額、上限、報酬単価は推定値で固定しない。

読み方：店舗責任者は第1〜6章・第14章、開発者は全章・付録A、検証担当は第12章を基準とする。v2詳細機能143件は付録Aに全件継承・改訂し、削除扱いにしていない。[B1：pp.5–11]

## 1. 業務フロー｜営業前から営業後まで

*採用方針 / Confidence：High*

| 順序・担当 | 操作 | 次工程へ渡す情報 |
| --- | --- | --- |
| 1　店長 | 営業イベント、料金、紹介者、許可枠、承認者、VIP在庫を設定。 | 営業日ID、ルール版、稼働担当者 |
| 2　紹介者 | お客様からLINE・電話等で連絡を受ける。アプリへ受付名・人数・条件を登録。 | 来店ID、紹介者ID、登録者ID |
| 3　サーバー | 期限・権限・常連事前許可・人数枠・禁止条件を評価。 | 受付可能／承認待ち／保留・不可 |
| 4　承認者（必要時） | 指定3名に通知。承認・却下・差戻しのいずれかを確定。 | 決定者、理由、対象版、確定条件 |
| 5　各入口担当 | 受付一覧が自動更新。通常登録に受領確認の操作は不要。 | 最新版の条件・人数・決済・同期状態 |
| 6　入口担当 | QRまたは名前で照合。支払・必要確認を行い、実際の入場人数を確定。 | 入場台帳、支払記録、残人数 |
| 7　紹介者・店長 | 自分のゲストの入場、全体人数、対象売上を確認。 | 紹介者別の暫定実績 |
| 8　店長・経理 | 未同期・会計差額・帰属争いを照合し、営業と報酬を締める。 | 確定レポート、報酬明細、調整履歴 |

### 業務上の原則

LINEはお客様との連絡手段として継続できる。置き換えるのは紹介者から入口への個別連絡、転記、既読確認、入場結果の問い合わせである。アプリ内チャットへの単純移行は中核要件の達成とみなさない。

営業日は店舗のタイムゾーンと開始・終了時刻で管理する。日付が変わっても当該営業を継続し、閉店・締めは別操作とする。同時開催イベントや別フロアを誤選択しないよう、常に営業名を表示する。

> 登録完了・料金条件の確定・入口への同期・実入場・売上確定は、別の状態である。いずれか一つの「完了」にまとめない。

## 1.1 現場シナリオ｜代表的な6ケース

*説明用の仮定例 / Confidence：High（計算）*

| ケース | 標準処理・期待する結果 |
| --- | --- |
| A：DJの割引ゲスト | DJ Aが2名・2,000円／人を登録。許可された割引なら承認不要で受付可能。2名の支払・初回入場で有料入場2名、入場料4,000円。 |
| B：信頼済み紹介者のフリー | 店舗が事前指定した常連紹介者Bに「当該営業3名までフリー」の許可がある例。2名登録は事前許可で確定。自己申告の常連タグでは成立しない。 |
| C：常連客の事前許可 | 顧客C本人に有効な「本人1名のみフリー」の事前許可がある例。本人照合用の識別子を紐付ける。同行2名には自動適用せず、別条件で判定する。 |
| D：到着済み・承認必要 | スタッフDが3名のフリーを申請。入口には要確認として表示。3名中1名が承認すると同じ来店情報が受付可能になる。待ち時間経過だけでは確定しない。 |
| E：分散到着・人数追加 | 5名中2名だけ先に入場。残り3名は未入場。追加2名は追加分だけ再判定し、既に有効な元の枠を無断で取り消さない。 |
| F：VIPの事前決済と精算 | 6名・事前20,000円、最終利用80,000円、当日残額60,000円の例。利用額は80,000円。デポジットや人数で二重計上しない。 |

### 異常時にも必要な動き

別の紹介者が同じ客を登録した場合は重複候補を提示し、氏名だけで自動統合しない。紹介者の帰属が未解決でも、本人・入場条件が確認できた来店者の受付を不必要に止めない。売上・報酬の帰属は未確定として保留する。

入口端末がオフラインなら、新規登録が即時届いたと表示しない。承認待ちの客を通信断を理由に自動でフリーへ切り替えない。暫定受付の扱いは第6.3節に従う。

上記の金額・人数上限は説明用。店舗の実設定・報酬条件として採用済みではない。

## 1.2 用語・「常連」の区別・責任範囲

*解釈を明示した要件化 / Confidence：Medium*

| 用語 | 本書での定義 |
| --- | --- |
| 紹介者 | プロモーター・DJ・スタッフ、および店舗が内部利用者として招待した紹介者。顧客を呼んだ人。 |
| 登録者 | 実際に来店情報を入力したアカウント。代理登録でも紹介者と別に残す。 |
| 常連紹介者／信頼済み紹介者 | 店長が事前指定した内部利用者。呼び名だけでは権限を持たず、承認省略許可を別途付与する。 |
| 常連客 | 来店するお客様。顧客の会員区分・来店履歴と、フリー等の事前許可は別データとする。 |
| 承認省略許可 | 誰に、どの店舗・営業・条件・人数・期間を許したかを記録する有効期限付きの権限／事前許可。 |
| 入場条件 | 通常料金・割引・フリー等の料金条件。適用時間、確認事項、対象人数を含む。 |
| VIP | 席・サービス区分。フリー／割引と排他的な選択肢にせず、入場料込み／別料金を明示する。 |
| 受付可能 | 条件判定上の入場候補。支払、本人・必要確認、残人数、取消などを入場時に再確認する。 |
| 実績・売上帰属 | 実入場と、識別可能な会計を紹介者に紐付けた集計。増分売上の因果証明ではない。 |

> 前提A-01：「常連」を、信頼済みの登録者と事前許可された常連客の双方に対応できるデータ設計とする。どちらを初回から有効化するかはD-01で店長が指定する。通常の顧客に内部画面を公開しない。

### 責任の分界

店長：料金・許可枠・常連指定・権限・例外ルールを承認。承認者：範囲外の申請を判断。紹介者：正しい受付情報を登録。入口：照合・支払確認・実入場を記録。経理：売上と報酬を照合。開発・運用担当：同期、権限、監視、復旧を提供する。

### PWAの案内・確認

iPhoneはSafari、Androidは対応ブラウザからホーム画面への追加手順を案内する。画面名・操作はOSとブラウザで異なるため実機で確定する。LINE内ブラウザのまま運用を開始させず、外部ブラウザへの案内を設ける。[W12][W13]

LINEログインは本人認証の手段であり、アプリの承認省略権限とは別である。OAuth/OIDCの戻り先・state・nonce等を検証し、クライアント側で渡された権限を信用しない。[W11][W14]

> 初期導入の受入：対象者全員が自分のスマホで起動・登録テストを完了する。PWA追加や通知許可のブラウザ検出だけでは完了とせず、本人の操作確認を残す。

## 4.1 承認不要／承認必要の判定ルール

*採用：承認分岐 / 詳細判定：Confidence Medium*

| 1 | アカウント・所属・イベントが無効、必須値不正、対象不一致 | 登録／更新を拒否。承認省略の評価へ進まない。 |

### 同行者・代理・退職の取り扱い

常連客本人だけの特典を選んだ場合は、本人と同行者を識別できる内訳を必要とする。常連客名を代表者名に入力するだけで全員に特典を付けない。権限者の代理登録も、実登録者の許可と代理対象の範囲を評価する。

利用者停止は以後の操作を止める。既に発行したゲスト枠を全件取消するかは別判断として明示し、停止の副作用で無通知のキャンセルを起こさない。重大な不正疑いは責任者が未入場分再審査を選択する。

### 現金・外部端末で支払った場合

入口担当が現金受領または外部決済参照番号を記録する。外部端末の結果を取得していない場合は、PSP連携済みと偽らず「店舗確認済み」と区分する。現金はシフト終了時に実金との照合を必要とする。

ID確認・ドレスコード等の確認項目は店舗ルールに基づく。身分証画像を標準では保存せず、確認実施の記録を最小限保持する。ルール自体の適法性は店舗側で確認する。

### キャンセル・No-show・メモ

キャンセルポリシーと同意時の版を保存する。失敗時は再決済リンクと期限を示し、期限切れの在庫解放・通知・再照合を行う。No-showは営業終了後、実入場・取消と区別して判定する。

VIPメモは用途別に閲覧を制限し、アレルギー等の情報は必要な範囲・同意・保持方針を確認する。予約見込み金額を実売上や損失と断定しない。

### 効果の測定計画：数字は未達成の目標

導入前2〜3営業と導入後4営業で、紹介ゲスト100件当たりの入口への確認往復数を比較する。ゲスト数・営業種別・受付人数を併記し、単純な営業件数差だけで改善を判断しない。

目標案：再確認80%減、営業後集計工数50%減、対象ゲスト登録率95%以上。常連枠の利用率・例外件数・精算訂正・問い合わせも測り、作業削減が別担当者の負担増に転嫁されていないか確認する。
