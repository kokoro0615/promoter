# 共用端末認証・担当者切替 v4

**採用：店舗共用端末／個人識別。詳細：設計案／Confidence：Medium。**

## 1. 認証の二層

個人PWA：招待→LINE/OIDC本人認証→所属確認→個人セッション。入口：管理者が端末ペアリング→device cookie→当日担当者選択→個人PIN→operator cookie。端末cookieだけでは候補担当者の最小一覧とunlockのみ許可する。ゲスト一覧を端末単独資格情報で返さない。

管理者の個人LINEで共用端末にログインしたまま渡す方式は禁止。ペアリングの承認は管理者自身の端末で行い、共用端末に残すのは専用の端末資格情報だけ。担当者アカウントは店舗所属に紐付く。[T06][T09]

## 2. セッションと境界

|証明|保存場所|用途|
|---|---|---|
|個人session|Secure・HttpOnlyの__Host-nc_personal cookie|個人PWA。APIが所属・操作権限を都度確認|
|device session|Secure・HttpOnlyの__Host-nc_device cookie|登録済み店舗端末の証明。人物の証明ではない|
|operator session|Secure・HttpOnlyの__Host-nc_operator cookie|その端末の現在担当者と営業|
|X-Operator-Context|画面に結び付けたoperator_session_id|古いタブの判定用。これ単体は認証情報ではない|
|PIN hash|サーバー側。saltとハッシュ、pepperは別管理|PIN照合。localStorageへのPIN保存禁止|

cookieのPath=/、Secure、HttpOnly、SameSiteは用途に応じ設計する。OIDCリダイレクトのstate管理と同一オリジンのCSRF対策を別々に試験。端末cookieと個人cookieを同時に持つ場合、暗黙の強い権限への昇格を避け、モードを明示する。[T06][T21]

## 3. PINとロック（提案初期値）

6桁以上の個人PIN、端末・担当者組み合わせで5回失敗したら300秒停止を初期案とする。端末単位・IP単位の異常試行も検知。ハッシュはArgon2id等を選定する。短PINはエントロピーが低いため、端末資格情報・サーバー試行制限・監査と組み合わせ、公開サイトのPIN単独ログインにはしない。[T08][T21]

無操作180秒、背景化は即ロック。絶対期限は12時間または営業終了の早い方。値はkiosk.schema.jsonの安全範囲で管理設定。自動pollやWebSocket heartbeatを人の操作とみなしてidle期限を延長しない。オンライン切断時にunlockしない。管理者PINリセットは本人管理セッションの追加認証・理由・旧operatorセッション失効を必須にする。

## 4. 交代と同時タブ

1. device行をロックし、現在epochを取得。
2. 旧operator_sessionを終了し、新担当者の所属・当日役割・PINを検証。
3. epochを増やし、新operator_sessionを作成。1端末1有効operatorの一意制約を守る。
4. cookieを更新し、全タブへロック／新コンテキスト通知。前担当の顧客詳細・入力途中の状態を隠す。
5. 旧タブからの書込はcookieが新担当へ変わっていてもX-Operator-Contextが一致せず409。新担当の操作へ付け替えて記録しない。

端末のロックや交代と処理中コマンドはdevice rowのロックで直列化する。先にコミットしたコマンドは旧担当として保存され、交代後に開始された旧コンテキストは拒否する。失効の意味を「ネットワーク途中の要求を時間的に遡って消す」ことと混同しない。

## 5. 通常入口承認の権限

有効なmembership＋当日ENTRANCE_APPROVER assignment＋登録端末＋operator sessionがそろえば、PENDING申請を直ちに判断できる。指定承認者の在席・既読・60秒経過・お客様の到着は不要。request_decisionのrouteはENTRANCE。入口通常承認のための代行理由は不要、却下・差戻し理由は必須。

自己申請の手動承認禁止はv3初期案を継承（D-03に確認残）。自分で許可範囲内の登録を行う経路は別の承認省略。入口の権限だけで恒久常連指定・料金設定・返金・報酬確定はできない。

## 6. 異常時

紛失は端末・セッションを停止。スタッフ停止は所属に依存するoperator sessionも失効。PINだけの変更と顧客招待取消は別操作。回線断は当日事前リストと単一受付の暫定記録のみ。認証が切れた端末を無制限のオフライン管理者にしない。

検収はAT4の共用端末・交代・停止・自己承認・他店舗試験。成功／失敗の証跡にPINやcookie値を残さない。

## 入口ロールの初期テンプレート

店舗が当日の入口担当を割り当てる標準操作は、ENTRANCEとENTRANCE_APPROVERの両方を設定し、通常から承認可能にする。閲覧専用・会計専用担当を作る場合だけ、管理者が明示的に承認権限を外す。指定承認者3名の人数枠に入口を押し込まない。入口の承認範囲と自己申請の扱いは権限表で確認する。
