# 認可・運用・移行・復旧チェックリスト v4

**設計要求／Confidence：Medium。法令・契約の適合性を確認済みとする文書ではない。**

## 1. 境界

tenant、store、event、membership、device、operatorの全境界をAPI、検索、購読、帳票、ストレージで検証。顧客が他店舗にも来ていても、同意や権限がない限り情報を自動共有しない。個人外部ログインIDは内部userへ、顧客IDとは別。

RLSは防御の一層。table owner、superuser、BYPASSRLS等は別扱い。[T03] ブラウザへ管理DB資格情報を渡さない。参照DDLはRLS有効・FORCE・PUBLIC権限なしの閉じた状態。本番では限定backendロール、読み取り射影、コマンド経由書込、membership/rowレベル認可と回帰テストを実装する。trustedなサーバー文脈だけでtenant/storeを設定し、利用者に任意SETを許す設計にしない。

## 2. データとログ

収集は受付名、必要人数、紹介者、条件、必要時連絡先・照合ヒントに絞る。身分証画像、個人LINEトーク、端末連絡帳、位置情報は標準取得しない。ロック画面通知に顧客詳細を載せない。PIN、cookie、アクセストークン、カード番号、Webhook署名鍵は監査ログへ保存しない。

監査対象：招待、役割、端末登録、PIN変更、担当切替、顧客指定、許可付与／取消、設定公開、登録、承認、入場、訂正、決済、返金、帰属変更、締め、出力。actor・対象・版・時刻・理由・端末・traceを保存。通常ユーザーにUPDATE/DELETEを許可しない。保持・匿名化・削除は別管理権限と手順で行う。

## 3. 導入・移行

店長が対象営業・料金・常連名簿・担当役割・端末を設定。個人PWA10名、入口共用端末の追加・起動・切替を実演。名前検索、承認省略、入口通常承認、同伴者、支払、部分入場、通信断、締めを通す。

CSV取込は試行検証→列対応→重複候補確認→確定→件数・人数・金額照合。取込ID・行source_keyを保存。氏名だけで自動統合しない。出力CSVの先頭=,+,-,@等は利用ソフトの式解釈を考慮して無害化する。原データは勝手に変えず出力表現として扱う。

移行期間も入場確定の正本はアプリに一本化。LINEをバックアップ参照に残しても紙とアプリで二重に確定しない。LINEだけ処理した案件を翌日照合する担当を置く。

## 4. 監視と夜間運用

APIの失敗・遅延、同期ACKの未達、承認滞留、端末切断、PIN試行、Webhook失敗、返金差額、hold期限遅延、outbox backlogを監視。各アラートに店舗責任者と夜間当番を設定。未選任なら本番ゲート未完了。値はplanning/decision_register.csvに管理。

## 5. 障害Runbook

|障害|一次担当|処理|復旧判定|
|---|---|---|---|
|端末1台不調|入口責任者|別登録端末へ交代、故障端末は確定禁止|snapshot再取得、担当者再認証|
|店舗回線断|入口責任者|予備回線、駄目なら単一暫定受付|暫定全件照合、二重・取消解消|
|承認API異常|夜間当番|エラー率・権限・枠・DBロック確認|正常承認と同時競合試験|
|決済応答不明|経理・運用|新規二重請求せずPSP照会|provider参照・金額・通貨一致|
|DB復元|運用責任者|書込停止、隔離復元、設定・鍵・ストレージを復旧|外部決済・inbox/outbox・入場を照合|
|担当者不明|入口責任者|端末ロック、本人切替、監査確認|個人識別の再確立|

## 6. バックアップ・公開

v3目標：99.9%可用性、RPO15分、RTO60分。達成・契約保証ではない。DBだけでなくストレージ・鍵・設定・外部PSPとの再照合が必要。復元試験は隔離環境で実施し、実際値を記録。保持期間・サポート時間・クラウド費用を合意してから本番承認する。

公開は旧版互換・DB拡張先行・段階切替。破壊的migrationをピーク時に自動適用しない。停止後のセッションと古いPWAが権限を復活させない試験を行う。
